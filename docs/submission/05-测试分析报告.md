## 4. 关键测试用例分析

### 4.1 格式误判和证据缺失

伪造 PCAP/PCAPNG magic、截断块、普通 raw DAT 和空文件均有测试。预期行为是只有完整容器进入抓包分支，raw DAT 的网络元数据保持 null。时间、方向或包边界缺失时，M09/M10 输出不可用原因，不能从字节位置推造。

### 4.2 消息结构正确性

M03 用带 ground truth 的长度字段样例验证边界 precision/recall/F1；M05 检查删除所有 gap 后是否精确重建原消息；M06 用小端剩余长度样例验证关系，并用固定长度/小样本确认不会生成伪长度字段。

### 4.3 正文恢复和资源上限

HTTP 测试覆盖双方向、多正文、Content-Length、chunked、压缩和离散范围。负例包括非法 chunk、截断 body、被替换的 stream/M01 父产物、尾随压缩数据、Base64 损坏、递归过深和压缩炸弹。预期是拒绝、partial 或 skipped，不留下可误用的 complete 结果。

### 4.4 分类防泄漏

M11 测试显式 partition 和 GroupKFold 的 group 交集为空；训练/测试类别不完整、单类别、无标签、非法数值或 `cluster_id` 标签均不产生准确率。预测前重新检查模型哈希和特征版本。ISCX 专项测试还会篡改 macro-F1、让会话同时进入两折、制造同名抓包歧义，均应失败。

### 4.5 模型与报告安全

模型适配负例覆盖未知 evidence ID、损坏响应、超时、响应过大和不受证据支持的安全结论。M12 测试确保输入哈希被重新验证、多实例不丢失、证据选择稳定，并且没有模型端点时仍能生成确定性报告。

## 5. 真实数据与验收结果

### 5.1 两个真实 DAT

- AudioBeat `dsp_m2.dat`：2387 字节，从偏移 5 切出 10 个 238 字节块；M04 得到 4 个探索簇；M05 10/10 对齐；M06 不虚构长度字段。
- WatchPAT `testdata.dat`：8469 字节，按 u32le payload length 完整切出 15 条 BLE 记录；M06 复现偏移 0 的 4 字节小端长度关系。

### 5.2 冻结 ABC 验收

正式验收记录为 `reports/acceptance/2026-09-11-abc/acceptance.json`。运行：

```powershell
python -B scripts\verify_acceptance.py reports\acceptance\2026-09-11-abc\acceptance.json
```

结果为 `acceptance: PASS`。恢复正文长度为 101 字节，SHA-256 为 `215ff970eee6a68f5e5a27bef8bea4026824a1e45d2c6024e79812617dee7c07`，与独立 truth 一致。该 PASS 表示证据链和验收规则成立，不会把 M03 partial 或 M06 empty 改写为模块语义成功。

### 5.3 公共与 ISCX 数据

21 个公共样例全部为 `completed_with_limits`，模块失败为 0。ISCX VPN 2016 使用 28 个参与会话、1028 条 flow，按 capture session 两折互补，macro-F1 均值 0.4995，多数类基线 0.3040。离线复核命令：

```powershell
python -B scripts\reproduce_iscx_evaluation.py verify
```

结果为 `ISCX evidence: PASS`。原始包未提交，因此本结果依赖 manifest 中记录的来源与哈希；脚本的 `prepare/train` 可在提供原始包后完整复跑。

## 6. 缺陷与风险分析

| 风险 | 影响 | 当前控制 |
|---|---|---|
| 课程指定 DAT 尚未提供 | 无法证明对隐藏输入的效果 | 明确隔离外部/自采数据，保留统一入口 |
| M03 是规则基线 | 任意未知协议可能无法自动分帧 | 输出 partial/未解析区间，不夸大 |
| M04/M05 为 O(n²)/O(mn) | 大样本资源开销 | 样本和 cell 上限 |
| ISCX 长会话截断 | 外部分类数字存在偏差 | 记录 20000 包上限和受影响会话 |
| ISCX 只有 VPN 子集 | 不能评 VPN 状态分类 | 仅声明 application 任务 |
| 无 Npcap | 当前电脑不能现场重采 | 使用冻结抓包；演示重采前单独安装 |
| 外部模型不稳定/付费 | 影响可选解释 | 默认不调用，确定性报告独立工作 |

## 7. 测试结论

当前代码、Schema、数据引用和验收门禁已形成完整可复核闭环，183 项自动化测试全部通过。系统对失败、证据不足和不可恢复情况具有明确状态，满足课程原型的稳定性和可解释性要求。剩余风险主要来自课程最终数据、真实成员信息和现场环境，而不是已知代码回归失败。
