# 任务分工说明

## 2. 共同任务

三名成员共同承担以下工作：

1. 评审 M01 的 packet/flow/stream 数据契约，保证下游模块不补造时间、方向和边界。
2. 修改生产者接口时同步更新消费者、JSON Schema、fixture、测试和文档。
3. 对跨线交付执行哈希、范围、Schema 和负例检查，而不是只检查文件是否存在。
4. 完成最终演示排练，分别讲解自己负责的模块和限制。

## 3. 协作和质量控制

- A 只消费 B/C 已冻结并通过契约检查的产物；分析入口不接受 truth 和测试标签。
- B 的正文恢复必须从 M01 重组流和严格 HTTP framing 推导半开区间，C 用独立 truth 检查恢复结果。
- C 的验收脚本独立检查 A 的运行清单、模块覆盖、恢复哈希、模型记录和分类器绑定。
- Git 历史、`docs/acceptance/handoffs/`、测试记录和冻结 manifest 是分工完成情况的证据；口头说明不替代提交记录。
