# 详细设计报告

## 1. 统一入口和任务图

`scripts/analyze.py` 读取输入与 `research/analysis-profile.schema.json` 校验后的 profile，按 `stages` 创建任务图。输入记录包含绝对/相对路径、长度和 SHA-256；工具记录包含 Python、平台和 TShark 版本。每个阶段结束后登记状态、耗时及 artifact 元数据。

profile 的 `reuse` 仅允许复用可重新验证的冻结产物。以 M01 为例，入口会验证 JSON Schema、packet/flow/stream 内部引用、二进制 artifact，以及 M01 原输入哈希是否等于本次输入；不能通过修改 profile 绕过输入绑定。阶段失败时删除运行目录，生成 `<output>.failure.json` 并返回非零退出码。

## 2. M01 输入与预处理

M01 先读取 magic 和容器结构。PCAP 检查全局头、字节序、版本、每条记录长度和尾部完整性；PCAPNG 检查 Section Header、byte-order magic、块长度与尾部副本。只有结构成立才进入抓包分支。

TShark 以受控字段集合导出包信息，包括时间戳、接口、捕获/原始长度、IP/端口、TCP stream、序列号、payload 长度和重传/乱序/缺口标记。系统按稳定 ID 生成 packet 和 flow，再依据 TCP 序列号去重重传并重组两个 node 相对方向的 payload。每个 stream artifact 保存长度和 SHA-256；缺包或截断使重组状态变为 partial。

## 3. M02-M06 未知二进制结构

M02 使用 256 桶统计字节概率，按 `H=-sum(p*log2(p))` 计算 Shannon 熵；窗口由 `window_size/window_step` 控制，短尾窗口仍被保留。重复片段使用确定性偏移排序，所有比例限制在 `[0,1]`。

M03 的三种规则为：固定长度按 `start_offset + n*frame_size` 切分；分隔符规则查找显式字节串；长度字段规则按给定偏移、宽度、字节序和长度语义计算消息终点。已接受消息内部的 magic 不会再次切分，所有未解析范围均显式输出。若有真值，可按边界集合计算 precision、recall 和 F1。

M04 先计算消息两两距离：长度归一化差与字节编辑差按配置权重组合，再用 DBSCAN 的 `eps/min_samples` 扩展密度可达集合。噪声记为 `-1`，代表消息必须来自原始样本。实现设置样本数量上限，因为距离矩阵空间和时间复杂度为 O(n²)。

M05 对每个簇选择代表消息，使用 Needleman-Wunsch 动态规划和确定性 tie-break 逐条对齐。输出每列的参考/样本字节、原偏移或 gap。去掉 gap 后必须逐字节恢复原消息，否则产物拒绝发布。动态规划单对复杂度为 O(mn)，因此设置 cell 数上限。

M06 对齐后统计每列 presence、主值比例、不同值数和数值分布，将连续相似列合并为固定/变化/可选区域。长度关系只在字段值与消息总长、payload 长或剩余长度对全部支持样本严格成立时提出，并记录宽度、大小端、基准和支持数；样本不足返回 insufficient，而不生成结论。

## 4. M07 协议解析

M07 消费 M01 及其原抓包快照，先复核来源哈希，再调用 TShark JSON 导出。只保留批准的 HTTP、TLS、DNS、FTP、邮件等字段，避免把任意工具输出直接注入报告。`recognition_mode` 区分 dissector、heuristic 和 decode_as；`visibility` 区分 metadata_only、partial_payload 和 application_visible。超时、输出超限、JSON 损坏或工具缺失都有合法降级结果且不保留半成品观测。

## 5. HTTP payload-source 与 M08 恢复

payload-source 构造器遍历 M01 两个方向的 TCP stream，要求严格合法的 HTTP 请求/响应起始行。对 `Content-Length` 验证非负十进制长度；对 chunked 编码逐块解析十六进制长度、CRLF 和终止块。每个正文记录父 flow/stream、方向、消息序号、一个或多个源范围、输出长度和 SHA-256。

M08 消费前重新验证 M01 父产物、stream artifact 和源范围重组结果。转换搜索包含文本编码、严格 Hex/Base64、gzip/zlib 等，每一步记录操作、输入输出长度和参数。相同输出字节去重但保留所有来源链。最大递归深度、单输出大小、累计输出、膨胀率和最小可打印长度限制资源使用。无密钥 TLS/SSH、Brotli、不完整 body 和损坏压缩流分别进入 skipped/failed/partial，而不是生成伪恢复。

## 6. M09-M10 流量行为

M09 对每个 flow 聚合包数、字节数、包长 min/max/mean/median/p95、两个方向计数与比例、方向切换、持续时间、包间隔、变异系数、突发和完整性指标。分位数使用 nearest-rank；无法计算的字段写入 `unavailable_features`。重传策略和 burst gap 都进入 parameters。

M10 的规则彼此非互斥。每条 observation 保存实际值、阈值、M09 evidence reference、confidence basis 和 limitation。时间缺失时只运行非时间规则；阈值非法或上游哈希不符时原子失败。输出仅描述模式，例如“方向主导”，不命名具体应用。

## 7. M11 分类

`build_rows.py` 从 M09 生成 17 维 v0.2 特征行，不附加标签。`prepare_rows.py` 在隔离步骤中注入外部 assignment 的 task label、group_id 和可选 split，并拒绝重复、幽灵 ID 或非法分区。

训练器检查行 ID 唯一、特征列完全一致、值为有限数且非布尔、标签维度合法，并禁止把 `cluster_id` 当行为标签。有显式 split 时分别构造 train/validation/test；否则使用 GroupKFold。任一 group 不得跨训练和评估，两侧必须包含全部类别。模型为固定随机种子 17、100 棵树、`class_weight=balanced` 的 RandomForest。模型通过临时目录写入，记录 joblib 长度、SHA-256 和 sklearn 版本后再发布。

`predict.py` 校验模型哈希、特征版本和列集合，对无标签行输出概率与拒识状态。`evaluate.py` 使用冻结模型评估带标签留出集，不重新训练。ISCX 复跑脚本按 capture session 分组生成互补两折，并独立复算混淆矩阵、逐类 F1、macro-F1、准确率、多数类基线和均值。

## 8. M12 与模型适配

M12 为各模块实现记录级 adapter，将来源、scope、location、observation、method 和 limitations 标准化为 evidence。输入允许同一模块多实例，但拒绝重复模块/路径对和无法解析的上游引用。稳定排序后生成 evidence ID，按数量/字节预算选择证据，并生成固定四章节报告。

DeepSeek 适配器只有在 `--invoke-model` 且环境中存在 `DEEPSEEK_API_KEY` 时工作。请求把证据标记为引用数据，响应必须符合受限 JSON 结构；引用未知 evidence、超限、超时或声称未经证据支持的漏洞/恶意性都会被拒绝。保存记录包含模型、请求与响应哈希、`key_persisted=false`，不含密钥。

## 9. 独立验收与打包

`scripts/assemble_acceptance.py` 将分析结果与分离 truth 组装成验收记录。`scripts/verify_acceptance.py` 重新验证输入、M01-M11 覆盖、artifact 哈希、M08 恢复字节、M11 模型/预测绑定及模型请求响应；PASS 只能由该独立检查产生。

`scripts/package_submission.ps1` 要求干净工作树，只复制 Git 已追踪文件，拒绝已存在输出 ZIP，最后写 `PACKAGE-MANIFEST.json`。manifest 保存 commit、UTC 时间、文件数量、每个文件的长度与 SHA-256，便于解压后核查提交内容。
