# 作品技术原理介绍

## 1. 研究问题

本作品面向来源不明的 `.dat/.bin/.pcap/.pcapng` 文件，目标不是凭扩展名猜协议，而是建立一条“从原始字节到可追溯结论”的分析链：识别输入容器、提取基础统计、提出消息边界、聚类与对齐、生成字段假设、调用成熟协议解析器、恢复满足条件的正文、分析流量行为、执行有标签分类，最后形成带证据引用的报告。

系统坚持三个原则：第一，缺少元数据时不补造；第二，候选模式不等于协议语义；第三，每一步都记录输入哈希、参数、范围和限制，保证结论可复查。

## 2. 分层分析原理

### 2.1 输入事实层

M01 采用内容优先的探测方式。PCAP/PCAPNG 需同时通过文件结构校验；确认是抓包后由 TShark 提取 packet、flow 和双向 TCP stream。普通 DAT 只保存原始字节，不虚构网络地址、方向或时间戳。每个二进制 artifact 都记录长度和 SHA-256。

M02 对任意字节输入计算长度、字节频率、Shannon 熵、ASCII/空白比例、重复片段和滑动窗口统计。熵只作为分布特征：高熵也可能来自压缩或随机数据，不能单独证明加密。

### 2.2 未知结构分析层

M03 使用显式规则进行消息分帧，支持固定长度、分隔符和长度字段。所有消息保存原始半开区间 `[start,end)`，未匹配前缀和尾部单独记录。TCP 分段边界不被当成应用消息边界。

M04 使用 DBSCAN 对消息聚类。距离由长度差和归一化字节编辑差组合，不强制预设簇数，并允许噪声点。若有独立标签，可计算 ARI/NMI；聚类编号本身绝不作为业务标签。

M05 以真实代表消息为参考执行字节级 Needleman-Wunsch 全局对齐。对齐单元同时保存字节值和原消息偏移，gap 与字节 `0x00` 严格区分。M06 再基于列稳定性、可选性和数值关系提出固定区、变化区、边界与长度字段候选。候选必须保留样本支持度，不直接命名业务语义。

### 2.3 标准协议与内容恢复层

M07 把成熟标准协议交给 Wireshark/TShark dissector，输出经过白名单筛选的协议字段、识别模式和可见性。端口只能作为上下文，不能单独证明协议；TLS/SSH 可被识别也不表示获得明文。

M08 的关键是先确定“恢复对象”。HTTP payload-source 解析器要求合法起始行和 framing header：`Content-Length` 对应一个连续范围，chunked body 对应若干离散范围。消费者重新计算父 M01、stream、范围重组结果和正文哈希后，才尝试 UTF、Hex、Base64、gzip、zlib 等有界转换。递归深度、输出大小和膨胀率均有限制；Brotli、无密钥加密和不完整传输明确跳过或标为 partial。

### 2.4 行为与分类层

M09 从包长、方向、时序、突发、重传和缺口等信息生成流级统计。特征只在上游证据存在时计算。M10 通过非互斥规则描述周期候选、方向主导、突发传输和长连接间歇行为，但不据此断言应用、用户意图或恶意性。

M11 将 M09 flow 转换为固定的 17 维特征。只有显式标签、有限数值特征和互斥 `group_id` 满足要求时才训练 Random Forest；训练与测试两侧必须都包含所有类别。同一采集会话不能跨训练/测试，以防数据泄漏。模型文件、特征版本和预测输入均由 SHA-256 绑定，低置信度结果可拒识为 `unknown`。

### 2.5 证据报告层

M12 将 M01-M11 的记录转换为稳定 evidence ID，生成“观测事实、解释与假设、无法判断、后续建议”四类内容。确定性报告不依赖外部模型。可选 DeepSeek 仅能解释已选择的证据，必须引用有效 evidence ID，并受请求/响应大小、超时和安全结论约束；API key 只存在于进程环境，不写入仓库。

## 3. 可追溯与独立验收

项目的信任链为：

```text
输入字节 SHA-256
  -> 模块产物 SHA-256 / Schema
  -> source_ref 与字节范围
  -> 恢复、分类和报告产物
  -> 独立 truth / 模型记录
  -> C 线验收门禁
```

统一入口在成功时生成 `run_manifest.json`，记录输入、profile、环境、阶段状态、耗时和全部 artifact；失败时删除半成品目录并写相邻 failure JSON。独立验收脚本不相信运行清单的文字状态，而是重新检查模块覆盖、文件哈希、正文 truth、分类模型绑定和模型响应引用。

## 4. 技术特点

- DAT-first：扩展名不决定格式，内容与结构证据决定处理分支。
- 证据保真：原始字节、偏移、方向、哈希和限制贯穿全链。
- 可降级：缺工具、缺标签、加密无密钥和证据不足都有机器可读状态。
- 原子输出：各模块拒绝覆盖已有输出，失败不留下可误用的正式结果。
- 防泄漏评估：分类按采集会话分组，而不是随机拆分相邻 flow。
- LLM 有边界：模型负责表达，不负责创造解析事实或决定验收。

## 5. 已验证效果与边界

两个真实外部 DAT 分别验证固定块和小端长度前缀结构；18 个自采 HTTP 抓包验证正文定位、恢复、分类与验收闭环；21 个公共样例验证不同协议/负例；ISCX VPN 2016 的 28 个会话、1028 条 flow 完成两折会话不交叠业务分类，macro-F1 为 0.4995，多数类基线为 0.3040。

上述结果证明原型流程可运行、可解释、可复核，但不代表对任意未知协议都能自动恢复语义，也不代表已经完成 VPN/non-VPN 状态分类。课程若提供新的指定 DAT，仍需作为独立输入重新验收。
