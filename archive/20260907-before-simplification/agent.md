# 网络加密流量二进制分析：Agent 调研执行规范

## 1. 任务与执行范围

你是本课设的技术调研与复现实验 Agent。依据用户提供的《网络加密流量二进制分析课设：技术调研与执行方案》，逐个完成 M1～M12 的检索、候选比对、复现或运行测试，并形成有证据的技术选型。

目标是在有限时间内验证可集成的完整分析链路：输入数据 → 协议解析识别或未知协议逆向 → 数据恢复 → 访问行为分析 → LLM 解释与报告。优先成熟工具，其次有官方代码的论文，再次可简化复现的统计方法。复用、集成和少量自主改进的投入参考比例为 70%、20%、10%。

本文件是后续执行指令。文中的工具、论文名称和建议算法均为待验证候选；不表示它们已安装、已核实或已通过测试。实际执行调研时，应持续完成检索、运行和证据归档，不能只输出计划或论文摘要。

默认交付调研报告、可重跑的模块 Demo、测试结果、接口方案及技术选型；完成选型后整理集成路线。完整平台开发、部署、状态机推断和大模型训练属于后续工作。

## 2. 执行顺序与进度管理

1. 阅读项目已有说明、代码、数据和研究记录，保留已有成果；检查 OS、Python、包管理器、tshark、Git、GPU 与可用运行环境。
2. 建立数据清单，优先确认 `.dat` 是连续字节流、带记录边界的数据，还是自定义容器。仅凭扩展名不能判定格式。
3. 按 M1 → M2 → M3 → M4 → M5 → M6 → M7 → M8 → M9 → M10 → M11 → M12 逐模块执行。当前模块完成报告和状态更新后再进入下一个；同一模块内部允许并行检索。
4. 工程集成时标准协议识别应在未知协议逆向之前分流。M1 可先做标准协议识别探测，正式能力比对与验收仍归 M7，避免重复实验。
5. 前置模块阻塞时，记录缺少的输入和影响，使用带真值的独立 fixture 验证下游模块；清楚标注尚未完成真实上下游联通。
6. 每个模块结束后更新 `research/progress.md`，记录候选、状态、关键证据路径、阻塞项与下一步。中断恢复时先读此文件，从未完成步骤继续。

模块状态：`not_started`、`searching`、`comparing`、`running`、`completed`、`blocked`。`completed` 表示调研闭环完成，可以得出放弃结论，不等于候选通过测试。跳过复现必须记录具体原因，不得将未测试模块写成已验证。

调研阶段建议控制在三天：首轮检索与候选筛选、集中运行与淘汰、补测与选型收敛。严格逐模块推进时，可将这三类活动压缩到各模块内部。不要为了遵守日期而省略实测或伪造完成状态。

## 3. 每个模块必须执行的闭环

### 3.1 明确问题与输入输出

写清该模块解决的问题、上游输入、最低输出、可用真值和验收方法。区分原始抓包、TCP 方向流、应用消息、消息字段与 Flow，禁止混用数据层级。

缺少用户 `.dat` 或其格式说明时，先用合成数据验证能力，记录真实数据适配未验证；不要因此停掉全部调研。

### 3.2 检索并核验来源

- 每模块至少执行一组项目检索和一组论文或算法依据检索。以官方仓库、官方文档、作者主页、原论文和正式出版页面为依据。
- 组合功能关键词、候选名称以及 `GitHub`、`official code`、`dataset`、`reproduction`、`Python` 等词。基础统计模块只需查清定义和可用实现，无须扩展为大型论文调研。
- 记录检索日期、平台、查询词、有效链接、筛选和排除理由。首轮保留最多两个候选，可加入一个轻量自研 baseline；只有候选均不适用时才继续扩展。
- 核验论文题名、作者、年份、DOI/arXiv/出版链接及代码归属。FieldWeaver、BPREN、PRE-Bin 等名称以检索证据确认，查不到时写“未核实”，不得补造论文或仓库。
- 区分作者代码、第三方复现、同名无关项目；阅读完整方法或与任务相关章节，搜索摘要只能用于发现线索。
- 检查输入限制、依赖、近期维护情况、许可证、数据可用性、训练/GPU要求，以及是否可独立调用。论文声称的效果与本地测量结果分别记录。
- 网络不可用时保留失败信息，继续本地文档、现有代码和 baseline 验证；外部资料标为待核实。

### 3.3 比对候选

先填项目调研卡，再建立同一模块内的对比表。逐项对照输入格式、输出语义、算法假设、训练需求、资源消耗、接口和当前环境兼容性。

M2、M8、M10 等优先自研模块，可比较“标准库/成熟库实现”和“简化算法 baseline”，不必为凑数安装大型项目。

### 3.4 强制运行与复现

1. 固定仓库 commit/tag、依赖与运行环境，在独立虚拟环境或已有容器环境中安装，保存完整命令和日志。
2. 运行官方最小 Demo 或相关自带测试，记录退出码、输出、首次运行耗时。
3. 用自己构造且带真值的简单数据运行一次，验证实际输入输出能接入本项目。
4. 补充一个正常变体与一个异常/边界用例；按模块要求做指标评估，并与 baseline 使用同一测试集。
5. 编写最小 CLI 或 Python 适配入口，输出结构化结果，证明可以独立调用；不要只保留 notebook 截图。
6. 保存日志、原始输出、指标、失败记录和必要补丁；用文档中的命令从固定输入重跑验收。

每个模块至少对一个主要候选执行实际运行尝试。未运行的次选方案必须注明，不能以相同证据强度排序。拟“直接采用”的方案必须通过 Demo、自定义数据测试及接口验证。

论文无代码时，允许实现独立的核心算法，标记为“核心方法简化复现”，说明与原文的差异。官方 Demo 成功不等于论文指标复现；只有对齐数据、划分、指标和实验条件后才能声称复现论文结果。

单候选首次验证以 2～4 小时为时间盒；依赖问题默认尝试至多两条有依据的修复路径，然后记录阻塞并测试替代方案。需要更长训练时，先完成小样本验证并给出资源估计，避免耗尽整个项目时间。

### 3.5 得出结论并进入下一模块

逐项给出：直接采用、简化复现、作为参考、放弃。结论必须引用来源或运行证据，并明确适用范围、剩余问题和预计集成时间。阻塞结论应附下一条可执行命令或缺失条件。

## 4. 十二个模块的具体任务

### M1 数据输入与预处理

- 检索候选：tshark、PyShark、Scapy、dpkt。关键词：`pcap TCP reassembly Python`、`tshark follow TCP stream`、`binary dat format detection`。
- 比对重点：PCAP/PCAPNG 支持、TCP 会话划分、按方向重组、乱序/重传处理、缺口表达，以及 CLI/Python 调用成本。核验能力由库本身还是自行补充代码提供。
- 运行测试：读取 `.dat/.bin/.pcap/.pcapng`；构造双向 TCP、多连接、分片到多个 TCP 段的消息、乱序、重传及截断样例。与发送端已知字节或可信解析结果逐字节比较。
- 最低输出：文件摘要、格式判断及依据、packet/flow/stream 清单、payload、来源偏移、可用的时间戳和方向。缺失元数据必须为 `null` 并说明原因。
- 验收：正常重组字节与真值完全一致；重复传输不重复计入应用字节；缺口和残缺数据可追踪。无网络元数据的 `.dat` 不能伪造 TCP 会话或时间信息。

### M2 二进制基础特征分析

- 检索与路线：核实 Shannon entropy、字节频率和滑动窗口统计定义，优先标准库/NumPy 的轻量实现。
- 必做特征：数据长度、256 维字节频率、全局/局部熵、ASCII ratio、zero ratio、重复模式、高频字节和固定前缀候选。明确 ASCII 范围、熵底数、窗口大小和尾窗规则。
- 运行测试：空输入、全零、固定文本、重复模式、0～255 等频字节和固定种子伪随机样本。
- 验收：全零非空数据熵为 0，等频 256 字节熵为 8 bit/byte，频率总和为 1；空输入返回约定状态，无 NaN 或除零。高熵只能提示压缩/加密/随机候选。
- 最低输出：带参数和来源范围的 `features.json`，以及与手工可计算样例的误差比较。

### M3 消息边界识别 / Framing

- 检索候选：Netzob 与轻量 framing baseline。关键词：`message boundary detection`、`protocol framing`、`protocol reverse engineering raw stream`。
- 核心核验：Netzob 是否能直接接收未切分的连续 `.dat`，还是需要已切分 Message List。必须检查 API 并实测，不能从“支持协议逆向”推定支持分帧。
- baseline：Magic、候选长度字段、delimiter、固定长度和重复模式；网络时序仅在存在真实时间信息时使用。
- 运行测试：已知真值的变长消息串联、跨 TCP 段消息、payload 内嵌伪 Magic、错误长度、前导噪声及尾部残帧。
- 最低输出：每条消息的 stream ID、半开区间 `[start,end)`、原始 bytes、分帧规则、证据和未解析区间。
- 验收：统计真实/预测边界集合的 precision、recall、F1 与完整消息匹配率，说明是否排除流首尾边界；受控正常样例边界精确匹配，异常样例不越界、不静默丢字节。没有可靠边界时保留候选或未切分状态。

### M4 消息聚类

- 检索候选：Netzob ClusterByAlignment、DBSCAN、K-Medoids 及协议消息聚类论文；首轮择两种可运行路线。
- 比对重点：length、byte/prefix similarity、entropy vector、n-gram 的效果；是否要求簇数、噪声处理、距离函数、时间和内存复杂度。
- 运行测试：至少三类带结构真值的消息，包含同类变长、不同类相似长度和离群样本；使用同一数据集对比 baseline。
- 验收：报告 ARI/NMI、噪声比例、簇大小及运行开销；无标签数据仅报告内部指标与人工结构检查，不称为分类准确率。
- 最低输出：message → cluster 映射、距离/特征配置、代表消息、离群样本和下游可消费接口。此模块须完成调研，完整聚类能力可按手册作为增强项。

### M5 消息对齐

- 检索候选：Netzob、成熟 Needleman–Wunsch 实现、PRE 序列比对项目。优先无需训练、能正确表达 0～255 字节值的实现。
- 比对重点：双序列与多序列能力、gap penalty、簇内变长消息处理、时间复杂度；文本/生物序列库的字母表限制要实测。
- 运行测试：固定头 + type + length + 变长 payload + 尾字段，加入插入/删除字节、空消息与含 `0x00/0xFF` 的 payload。
- 验收：gap 使用独立标记而非真实字节；移除 gap 后必须精确还原输入，各对齐行等长；检查已知固定字段位置和插删变体。对齐结果不能直接冒充字段语义真值。
- 最低输出：对齐矩阵、gap 表示、原始 offset 映射、参数和带真值的对齐检查结果。

### M6 字段边界 / 协议格式推断

- 检索候选：Netzob、经核实的 FieldWeaver/BPREN/PRE-Bin 类方法，以及传统统计 PRE。选一个成本可控的核心方法与统计 baseline 比较。
- baseline 特征：按位置 entropy、unique count、variation ratio、length correlation、adjacent mutual information。明确变长消息的有效样本数及 gap 排除规则。
- 比对重点：是否依赖预分帧/聚类/对齐、固定和变长字段能力、训练成本，以及能否只复用字段推断部分。
- 运行测试：带 Magic、type、大小端 length、可变 payload、计数器与已知 checksum 的合成协议；增加独立生成的留出样本检验候选规则。
- 验收：报告字段边界 precision/recall/F1、长度规则匹配率和留出集表现。明确 length 是否含头、含尾或仅 payload；高相关性只形成候选，需验证具体长度公式。Checksum 必须验证算法，否则只标为候选尾字段。
- 最低输出：字段范围/动态定位规则、候选语义、样本数、统计证据、候选关系与置信度依据。无校准置信度不得伪装为准确概率。

### M7 标准协议识别与解析

- 检索候选：Wireshark/tshark dissector 及其官方调用方式，评估 HTTP、SMTP、POP3、IMAP、FTP、TLS、SSH、DNS 的覆盖情况。
- 运行测试：至少用 HTTP、DNS、TLS 三类带真值抓包做冒烟测试，其余目标协议逐项登记已测/未测；补充未知协议、端口伪装和截断样例。
- 比对重点：协议识别与端口猜测的差异、重组需求、结构化字段输出、启发式 dissector 和 decode-as 的使用条件。
- 验收：输出协议、实际字段和识别依据；显式配置 decode-as 不能计为自动识别。未知数据返回 Unknown，并可交给 M3～M6。
- 原始 `.dat` 缺少网络头时不得假装为 PCAP 直接解析。必要时建立明确标记的包装适配，记录人工补充的封装信息及对识别结果的限制。

### M8 明文提取与数据恢复

- 检索与比对：标准库/成熟库实现文本、Hex、Base64、gzip、zlib 检测恢复；XOR 作为实验增强；有实验密钥时才验证对应解密路径。
- Pipeline：直接文本 → 编码 → 压缩 → 简单变换 → 加密协议判断。支持受限的多层解码，记录每次转换的输入、输出、参数和偏移来源。
- 运行测试：ASCII、UTF-8、JSON/XML、Hex、Base64、gzip/zlib、嵌套编码压缩、非法编码、截断压缩包和随机字节；包含已知 TLS 或有真值的加密样本。
- 验收：已知恢复结果按 bytes/hash 精确匹配；同时报告成功恢复率与负样本误报率。XOR 输出可读不代表恢复成功，需结构或真值验证。
- 限制转换层数、输出体积与解压膨胀比例。无密钥强加密标记不可恢复；仅凭高熵标为疑似，不宣称确认 AES/TLS。
- 最低输出：恢复产物、变换链、原始关联、状态与失败原因。消息状态采用互斥主分类统计，多层变换次数单列，避免重复计算“恢复消息数”。

### M9 流量统计特征

- 检索候选：CICFlowMeter 与简化自研统计，核对具体仓库和特征定义，避免混用不同实现的同名特征。
- 必做：packet size/direction/inter-arrival time；flow duration/count/bytes、上下行 bytes、包长均值/方差；burst count/size、active/idle time。
- 运行测试：手工可计算的小型抓包、双向传输、同时间戳、单包 flow、空输入；固定 burst 阈值、flow timeout 与方向判定规则。
- 验收：计数与字节求和精确一致，浮点量在预先声明容差内；注明包长是链路层、IP 还是 payload 长度，方差是样本或总体方差。
- 原始 `.dat` 没有时间戳/方向时相关特征为缺失值；不能按字节 offset 推造时序，也不能把应用消息数当网络包数。
- 最低输出：packet/flow/burst 特征表、单位、公式、缺失信息及与真值的对比。

### M10 数据访问行为分析

- 检索与路线：核验流量统计驱动的规则方法，优先规则 + M9 特征，输出可观察行为描述。
- 运行测试：周期性小包、持续下行、集中上行、短交互、突发流量等带真值特征序列；补充缺失时序/方向和阈值邻域样例。
- 验收：每条“长连接”“下行占主导”“周期性突发”等描述都有特征值、单位、阈值和规则 ID；证据缺失时输出不足以判断。
- 最低输出：行为描述、触发规则、引用特征与局限。不要将通信形态直接认定为恶意行为或具体应用类别。

### M11 数据访问行为类型分类

- 检索：`encrypted traffic classification`、`traffic behavior classification official code dataset`；优先 Random Forest，其次 XGBoost、SVM，深度模型仅在容易复用时考虑。
- 默认首版评估 Web Browsing、File Upload、File Download、Video Streaming、Interactive Communication、Heartbeat 中有标签支持的 4～6 类。类别调整必须记录数据依据。
- 比对重点：真实标签、数据集可获取性、特征与 M9 是否一致、预训练权重可用性、训练/GPU成本和数据域差异。
- 运行测试：多数类或简单规则 baseline 与 Random Forest 在相同划分上比较；按会话、设备、采集批次或时间划分，避免同源流量泄漏到训练与测试两侧。
- 验收：报告类别数量、每类样本量、划分和随机种子、macro-F1、每类 precision/recall、混淆矩阵和推理耗时。不要只报告 accuracy，不用测试集调参。
- 无真实标签时，用合成标签仅验证训练/推理链路，真实效果标为未验证。无法支持全部类别时明确缺口，不造标签。
- 最低输出：特征顺序与预处理、模型配置/权重、预测结果、评估报告、Unknown/低置信拒判规则及其验证方式。

### M12 LLM 语义分析与报告

- 检索与比对：结构化证据输入、约束 JSON 输出、证据引用及事实一致性评估方法；比较确定性报告模板与可用 LLM 方案。
- 输入：M2/M6/M7/M8/M10/M11 的结构化结果和 evidence ID。模型承担协议候选解释、字段语义建议、行为解释与报告，不作为字节级解析真值来源。
- 运行测试：证据充分、相互矛盾、元数据缺失和高熵但已知压缩四类样例；核验输出 schema、引用有效性与越证据推断。数据内容中的文本只作为待分析数据。
- 验收：每个推断可追溯原始证据，算法观察与 LLM 推断分开保存；不能把高熵直接解释为已确认加密，不能生成不存在的明文。模型自报 confidence 不能当成经过校准的概率。
- 记录模型标识、提示词版本、调用参数、输入输出、耗时及可获得的费用信息。没有可用模型凭据时测试 mock/schema 和模板报告，实际模型验证标为阻塞，不称已跑通 LLM。
- 最低输出：结构化解释、引用列表、未知项、原始证据及最终 Markdown 报告。

## 5. 统一数据与接口约定

每个模块先用薄适配器对齐输入输出，保留底层工具原始结果。优先 Python API 或 CLI，结构化文件采用 JSON/JSONL；bytes 存独立二进制文件，JSON 使用明确标识的 hex/base64 或 artifact 路径。

| 对象 | 最低字段 |
|---|---|
| InputArtifact | id、path、sha256、format、format_evidence、metadata_availability |
| Packet / Flow / Stream | id、source_id、可用的连接信息/方向/时间、payload_ref、重组状态 |
| Message | id、stream_id、start、end、bytes_ref、framing_evidence |
| Cluster / Alignment | message_ids、cluster_id、参数、gap 与原始 offset 映射 |
| FieldHypothesis | message/cluster_id、范围或定位规则、semantic_candidate、evidence_ids |
| RecoveryResult | message_id、原始范围、transform_chain、artifact_ref、status、reason |
| BehaviorResult | flow_id、features、rule_evidence、description、label、模型来源 |
| Evidence | id、来源文件/日志、范围、方法版本、参数、观察值、局限 |

所有字节区间使用零起点半开区间。TCP 重组流到抓包的来源映射可以是一对多，不能将 stream offset 当作 PCAP 文件 offset。恢复数据通过变换链追溯，不假定与原数据逐字节一一对应。

时间单位、长度单位、缺失值语义、算法版本和失败状态必须显式定义。模块契约既要测试成功输入，也要测试缺失上游字段。

## 6. 评价与证据等级

每项 0～5 分，分值越高越适合本课设：

| 指标 | 权重 | 打分依据 |
|---|---:|---|
| 需求匹配 | 25% | 实际覆盖本模块必需输入输出 |
| 易运行 | 20% | 安装和首次实测成本 |
| 易集成 | 20% | API/CLI、数据适配与依赖隔离成本 |
| 稳定性 | 15% | 正常、变体、异常测试表现 |
| 算法效果 | 10% | 同条件测试指标及适用范围 |
| 可解释性/答辩效果 | 10% | 原始证据、结果复核与展示能力 |

总分（0～5）= 0.25×匹配 + 0.20×易运行 + 0.20×易集成 + 0.15×稳定 + 0.10×效果 + 0.10×可解释。

未经实测的运行、稳定性或效果项填 `N/A`，不强行补分或与完整实测总分直接排名；可另给“文档预评估”，注明推测依据。评分附证据路径。输入不匹配、不可调用或未通过必需验收时，即使预评分高也不得直接采用。

候选证据等级：E0 来源已核实；E1 安装/构建通过；E2 官方 Demo 或测试通过；E3 自定义数据和边界测试通过；E4 公平对比与接口验证完成。论文指标复现单独标记，不由 E4 自动推导。

## 8. 贯通测试与最终交付

至少设计以下三档测试，共用可追溯的输入与真值；合成样例只验证受控条件能力，不能代替真实数据泛化结论。

| Case | 数据 | 验证链路 | 验收重点 |
|---|---|---|---|
| A 标准明文协议 | HTTP/DNS 等已知抓包 | M1、M2、M7、M8、M9、M10、M12 | 协议与关键字段正确、payload/文本按真值恢复 |
| B 自定义二进制 | 固定头、type、length、变长 payload、尾字段的 `.dat` 与独立真值 | M1～M6、M8、M12 | 分帧/字段指标、对齐保真、数据恢复精确匹配 |
| C 加密流量 | 已知 TLS 抓包，含密钥的实验样例可选 | M1、M2、M7、M8～M12 | 协议元数据、恢复边界、行为证据及标签评估 |

M11 另需独立有标签数据及无泄漏测试划分；不能仅凭上述三个样例认定行为分类有效。贯通测试中保留 Unknown、残帧、缺少时间信息和不可恢复数据的处理结果。

最终必须交付：

1. M1～M12 的检索日志、候选卡、比较表、模块报告；每个模块有运行尝试或可核实的阻塞证据。
2. `selection.md`：每个需求对应的项目/论文/自研实现、版本、评分、证据等级、选择理由、备选方案和集成成本。
3. 所有拟采用模块的可运行 Demo、依赖说明、输入 fixture、测试、原始日志、指标及重跑命令。
4. `architecture.md`：输入、标准协议/未知协议/高熵数据路径、接口和结果融合；高熵路径与协议路径允许重叠，高熵不构成强加密判定。
5. `risks.md`：如连续 `.dat` 无法直接导入 Netzob、论文代码缺失、元数据不足、行为标签缺失、依赖难以运行，并列出已验证替代方案。
6. `final-report.md`：协议识别、结构候选、数据恢复统计、行为分析、证据链接，以及通过/失败/未测试的范围。

停止扩展检索的条件：12 个模块均已形成证据支持的选择或阻塞结论，所有拟直接采用模块完成 E4，三档贯通测试已执行或具体缺口已登记。若存在阻塞，结项必须标注“部分完成”，不得宣称整个系统验收通过。

## 9. 技术边界与真实性要求

- 必做能力按手册覆盖：`.dat` 读取、基础特征、消息识别/对齐/统计、字段推断、标准协议解析、payload 和 ASCII/Base64/压缩恢复、加密候选检测、Flow 特征、行为描述/分类、LLM 解释。
- 聚类、自动 length/opcode 推断、XOR、TLS 元数据深化和字段置信度作为增强；状态机、深度学习分类、FieldWeaver 完整复现、多 PRE 融合放在基础闭环完成之后。
- 不把无密钥破解 TLS/AES、通用未知协议 100% 恢复、自研 TCP 协议栈或完整协议库列入目标。
- 不编造检索链接、实验运行、准确率、日志、恢复明文或论文结论。示例数据、人工标注、推断结果、算法实测结果应明确区分。
- 原始输入保持不变；实验产物单独保存。每项结论必须能回答：依据是什么、实际跑过什么、如何重跑、适用条件是什么。
