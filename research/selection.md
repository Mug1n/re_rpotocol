# 模块初步选型

更新：2026-09-07。M1～M12 资料比较已完成；以下是初步建议，不是实测性能排名或集成承诺。来源、输入输出和待核实项见各模块报告。

## 总体技术路线与选型理由

验收时可将方案概括为“先确认输入事实，再逐层增加推断”：M1 先判断 DAT 是裸字节、抓包还是其他容器；M2 对所有输入给出不依赖协议的基础统计；只有具备连续流或消息依据时才进入 M3～M6；确认是标准网络协议后优先交给 M7 的成熟解析器；具备编码、压缩或解密条件时由 M8 恢复内容；只有保留包边界、时间戳和方向时才执行 M9/M10；M11 需要口径一致、来源可追溯的流特征和明确标签，也可直接使用符合条件的预计算特征；最后由 M12 根据带来源的结构化证据生成解释。

这条路线优先选择可解释、依赖条件清楚且能保留原始偏移的工具和算法。成熟标准协议由 TShark 处理，避免重复实现 dissector；未知协议使用规则、统计、聚类和对齐逐步提出假设；M4 可在无标签消息上进行无监督聚类，监督式行为分类只在标签存在时使用；LLM 只负责组织和解释证据。这样既覆盖课程要求，也避免把端口、高熵、聚类编号或模型输出误当成协议和业务真值。

| 模块 | 初步推荐 | 推荐理由（主要特点） | 限制与待核实项 |
|---|---|---|---|
| [M1 数据输入与预处理](M01-input/report.md) | 原始字节读取/内容识别 + TShark 抓包分支 | 区分裸 DAT 与抓包，利用已有解析能力 | DAT 封装未知；入口适配待开发 |
| [M2 二进制基础特征](M02-features/report.md) | 标准库为基础，NumPy 批量加速备选 | 长度、频率、熵、字符比例、重复片段及窗口统计 | 高熵不是加密证明；窗口尺度待定 |
| [M3 消息边界](M03-framing/report.md) | 已知协议 TShark；未知流用 Magic/长度/分隔符/定长假设 | 规则可解释，保留残片和原始偏移 | TCP 重组不等于分帧；无规则时保留未知，Netzob 不作为通用自动分帧保证 |
| [M4 消息聚类](M04-clustering/report.md) | DBSCAN；需代表样本且 k 明确时用 K-Medoids | 不预设簇数且可标噪声，支持特征或距离矩阵 | 需可靠消息样本和合适距离；变长 bytes 不能直接输入；簇不等于业务类别 |
| [M5 消息对齐](M05-alignment/report.md) | 字节级全局双序列对齐；集合操作考虑 Netzob | 通过 gap 表示插入删除并保留偏移映射 | 多消息组织需额外方法；评分、重复区域与规模影响结果 |
| [M6 字段与格式](M06-fields/report.md) | 按列统计基线；NEMESYS 作为论文/开源候选 | 基线可解释；NEMESYS 利用单消息内部变化估计边界 | 基线依赖分帧/聚类/对齐；NEMESYS 仍需消息范围，且旧依赖兼容性待核实 |
| [M7 标准协议](M07-standard-protocols/report.md) | Wireshark/TShark | 覆盖 HTTP、邮件、FTP、TLS、SSH、DNS 等解析器 | 识别有封装与可见性条件；端口不是证据，支持 TLS 不代表获得明文 |
| [M8 明文与恢复](M08-recovery/report.md) | 标准库解码/解压 + 协议对象导出 | 文本、Hex、Base64、gzip/zlib 与来源链 | 编码、压缩和加密必须区分；缺包或无密钥限制恢复 |
| [M9 流量特征](M09-flow-features/report.md) | 轻量自定义统计；CICFlowMeter 作公开集兼容备选 | 定义明确、缺失逐项说明；备选提供双向流 CSV | 需要包边界、时间与方向；裸 DAT 不能补造流特征 |
| [M10 行为描述](M10-behavior-analysis/report.md) | 规则统计，辅以自相关/周期图 | 解释周期、方向主导、突发与长连接 | 阈值和观测窗口依赖场景，模式不等于应用或恶意性 |
| [M11 行为分类](M11-behavior-classification/report.md) | 有标签后首选 RF 基线；XGBoost/SVM 作比较 | 表格特征分类；ISCXVPN2016 提供类别与数据线索 | 需训练及真实标签；旧公开数据可能偏移，无标签时仅给 M10 描述 |
| [M12 LLM 报告](M12-llm/report.md) | 结构化证据 + LLM 解释 + 引用核对 + 模板 | 本地 llama.cpp 可选；小规模材料直接选入，无需先建向量库 | 运行器不等于模型；部署条件与质量待核实，合法 JSON 不保证事实正确 |

适用分支：所有输入可以先做 M2；已确认网络封装时才用 M7 和包级元数据驱动的 M9。未知流需先提出 M3 边界，再进行 M4～M6。M8 只恢复满足编码、压缩或解密条件的可见内容；M10/M11 的缺失证据必须传给 M12。

进入开发后的首要核实项是实际 DAT 的封装、包/消息边界、时间戳和方向，以及行为标签是否存在。当前不因这些未知项继续扩展候选或恢复历史实验待办。
