# M12 LLM 语义分析与报告

状态：已完成 M01～M11 跨线集成。检索日期：2026-09-07；2026-09-09 已实现 M01/M02/M07～M11 细粒度适配、稳定证据 ID、四章节报告、模块化上游哈希校验、M07→M01 作用域校验和有界输入/证据处理。

用途：把可追溯的解析与统计结果组织为解释、假设和报告，不替代底层证据生成。

| 候选 | 主要特点与优势 | 输入输出及前置条件 | 限制 | 来源 |
|---|---|---|---|---|
| 结构化证据 + 本地 LLM（llama.cpp server） | 本地推理，支持 CPU/GPU 和受 schema 约束的 JSON，便于接模板 | 精选证据、指令及适配的模型权重/聊天模板 → 结构化解释 | llama.cpp 是运行器而非模型；需兼容权重、足够内存与上下文，JSON 合法不保证事实正确 | [官方 server 文档](https://github.com/ggml-org/llama.cpp/tree/master/tools/server) |
| 证据检索增强（RAG 思路） | 在生成前提供相关协议文档、模块发现及其出处 | 问题 + 可检索资料库/人工挑选材料 → 带证据引用的解释 | 检索到错误或不相关资料仍会误导；原论文不是未知协议恢复能力证明 | [Lewis 等原论文](https://arxiv.org/abs/2005.11401)；本项目应用为设计推论 |
| 确定性模板报告（拟开发） | 固定填入已知数值和证据链接，无模型也能出报告 | M1～M11 的结构化结果 → Markdown/HTML | 不具备开放式语义推理，是报告基线与降级路径 | [Python 模板字符串](https://docs.python.org/3/library/string.html#template-strings) |

后续建议仍是“结构化证据 → 语义支持校验 → LLM 解释 → 模板呈现”，但当前没有能够判断引用内容是否真正支持模型陈述的有界校验器。因此本版本完全禁用模型适配器执行，只发布确定性证据报告；本地或托管模型均不会被调用。

建议输入记录包含 evidence_id、模块、文件/流/消息标识、原始偏移、时间范围、指标单位、实际值、方法及缺失信息；输出把“观测事实”“解释假设”“不能判断”“后续建议”分开，事实和假设均关联 evidence_id。字段名称、协议识别和统计数值以解析结果为准，模型不得补造；引用标识存在也不代表支持该结论，仍需核对内容。

字节串、提取文本和外部文档均作为待分析数据，不能把其中命令当指令执行。只提供必要片段及统计摘要，避免将整份密文当语义提示；上下文截断应明确记录。上述证据组织与核对流程为拟开发方案，没有运行验证。

本地验证边界：M01～M11 全部提供时可生成 `complete` 报告；缺失模块会保持显式 `partial`。输入在 JSON 读取前受字节上限约束，证据记录在规范化时即受数量上限约束。传入模型适配器只会产生固定禁用警告，不执行适配器，也不会在报告中呈现模型文本。未来只有在执行超时、Markdown 安全呈现和语义支持校验同时具备后，才可重新启用模型路径。LLM 不能从密文凭空解密，也不能把 M10 模式推测升级为已证实的 M11 业务类别。
