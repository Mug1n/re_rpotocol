# M5 消息对齐

状态：已实现并完成基线验证。初始检索日期：2026-09-07；实现及真实 DAT 复测日期：2026-09-08。

用途：在同类消息间定位稳定片段与插入、删除区域，为字段候选提供位置关系。

| 候选 | 主要特点与优势 | 输入输出及前置条件 | 限制 | 来源 |
|---|---|---|---|---|
| Needleman–Wunsch / Biopython PairwiseAligner | 支持全局双序列对齐和可调 gap；整数序列可表示全部字节值 | 两条已切分消息映射为 int32 的 0～255 序列 → 得分和位置映射；无需训练 | 是双序列能力，多序列需额外方法；算法随 gap 设置选择，仿射 gap 可能使用 Gotoh | [官方教程：整数序列与 gap](https://biopython.org/docs/latest/Tutorial/chapter_pairwise.html) |
| Netzob | 面向消息集合的对齐与不变片段识别，可与格式推断衔接 | 同类消息集合 → 对齐/字段候选 | 集合处理不代表全局最优多序列解；接口及二进制粒度需按选定版本核实 | [官方概述](https://netzob.readthedocs.io/en/latest/overview/) |

## 当前实现

已用标准库实现字节级 Needleman–Wunsch 全局对齐，以 M4 的真实代表消息为锚，将各成员的双序列结果按参考偏移和插入锚点合并为统一列。每个非 gap 单元保存 `[原消息偏移, 字节值]`，gap 保存为 JSON `null`；M4 噪声不强行对齐。输出记录评分、匹配、错配、两类 gap、配对字节一致率和来源哈希，并提供 JSON Schema。

默认评分为 match `2`、mismatch `-1`、gap `-2`，单对默认最多 2,000,000 个动态规划单元。算法只保留完整 traceback 方向矩阵和两行分数，空间仍为 O(mn)，但避免保留完整 Python 整数分数矩阵。输入一致性检查覆盖 M03 artifact 长度与路径、M04/M03 哈希、消息集合、噪声及簇成员关系。

真实结果：Audiobeat 在 M04 `eps=0.11` 的 4 簇中对齐 10/10 条消息，4 簇合计 955 列，平均配对字节一致率 0.968390。WatchPAT 默认单簇对齐 15/15 条消息，代表消息 563 字节、统一后 801 列，平均一致率仅 0.487364，说明默认 M04 分组可能过粗；将 M04 收紧到 `eps=0.11` 后为 4 簇、2 条噪声，对齐 13/15 条，平均一致率提高到 0.613779，但轮廓系数仅 0.139845，仍不能视为可靠协议类别。

字节应作为一个符号，避免直接对 Hex 字符串逐字符对齐而出现半字节错位。gap 是额外的“缺失位置”，不能用 0x00 表示；输出保留对齐列到原消息偏移的映射。经典完整动态规划通常需要 O(mn) 时间与矩阵空间，大消息、全对全比较成本较高。变长字段可通过 gap 表示，但匹配/错配和 gap 代价会影响结果。

待核实：更大数据上的评分敏感性、仿射 gap 和超长消息优化。当前是确定性的代表参考对齐，不是全局最优多序列对齐；重复区域中等价 gap 的落点会受评分和 tie-break 影响。重复填充、压缩或密文可能产生偶然匹配；对齐得分不能证明字段语义或协议相同。分帧错误应先回到 M3 处理，低质量簇应回到 M4 调参或拆分。
